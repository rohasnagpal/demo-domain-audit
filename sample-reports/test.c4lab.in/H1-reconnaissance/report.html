lowH1-001

X-Powered-By header discloses application technology

Control H1-WEB-002 · Information disclosure

What this control checks

Checks whether X-Powered-By or similar headers disclose the application framework or language version.

What we found

https://test.c4lab.in returns: X-Powered-By: PHP/5.6.40

Why it matters

Framework and language versions, such as PHP/8.1.2, are high-value fingerprinting data. Application-layer vulnerabilities are usually tied to a specific version.

How an attacker would use it

An attacker matches the disclosed version against known application or interpreter vulnerabilities.

Why low

Low: disclosure only.

How to fix it

  1. PHP (php.ini, or the host's PHP settings panel):
    expose_php = Off
  2. Express (Node.js):
    app.disable('x-powered-by');
  3. Apache with mod_headers (.htaccess):
    Header always unset X-Powered-By

Rollback

Re-enable the setting.

How to verify the fix

curl -sI https://test.c4lab.in | grep -i x-powered-by

lowH1-002

HTTP Strict Transport Security (HSTS) not enforced

Control H1-WEB-004 · Transport security

What this control checks

Checks for a Strict-Transport-Security (HSTS) header with a max-age of at least six months, which tells browsers to use only HTTPS for the site.

What we found

The HTTPS response from https://test.c4lab.in has no Strict-Transport-Security header.

Why it matters

Even with an HTTP-to-HTTPS redirect, a browser's first request to http://test.c4lab.in goes out unencrypted, and the redirect itself can be intercepted. HSTS tells the browser to rewrite every future http:// request to https:// itself, before anything is sent, and to refuse to click through certificate warnings for the site.

How an attacker would use it

SSL stripping (sslstrip): an attacker on the network intercepts the initial HTTP request, suppresses the redirect and proxies the site to the victim over HTTP while talking HTTPS to the real server.

Why low

Low: requires an on-path attacker and a user who reaches the site over HTTP first.

How to fix it

  1. Apache (.htaccess or virtual host, with mod_headers):
    Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"
  2. nginx (inside the HTTPS server block):
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
  3. Start with a short max-age (for example 300) and increase it once every subdomain works over HTTPS. includeSubDomains applies the policy to every subdomain.
  4. Optionally, once stable, add "; preload" and submit the domain at hstspreload.org so browsers enforce HTTPS from the first visit.

Rollback

Set max-age=0 to tell browsers to forget the policy.

How to verify the fix

Run
curl -sI https://test.c4lab.in | grep -i strict-transport
Expect
strict-transport-security: max-age=31536000; includeSubDomains

Server header discloses web server software

Control H1-WEB-001 · Information disclosure

What this control checks

Checks whether the Server response header discloses the web server product or version.

What we found

https://test.c4lab.in returns the header: Server: Apache The product is disclosed but not its version.

Why it matters

Knowing the product (Apache) narrows down which attacks and misconfigurations to try. It is minor because the version is hidden and the product can usually be identified by other means anyway.

How an attacker would use it

Product-specific probing, such as Apache-specific paths and modules, without needing to fingerprint first.

Why informational

Informational: product-only banners are common and give little advantage.

How to fix it

  1. No action is required. If you control the server and want to remove the header entirely, use a reverse proxy or CDN that rewrites it, or Apache's mod_security SecServerSignature.

Rollback

Not applicable.

informationalH1-004

Public DNS reveals third-party services

Control H1-DNS-001 · Information disclosure

What this control checks

Identifies the third-party services the domain's public DNS reveals (email, DNS and web hosts, SaaS verification tokens and SPF senders), the information an attacker gathers first.

What we found

Public DNS for test.c4lab.in reveals these providers and services: • Email: DreamHost Mail (MX mx1.dreamhost.com)

Why it matters

This is normal and largely unavoidable: SPF, MX and verification records must be public to work. It is reported so you know exactly what an attacker learns in seconds.

Each service is a phishing pretext ("Your Google Workspace password expires today") and an account to protect. Verification tokens for services you no longer use add noise and can indicate forgotten accounts still linked to the domain.

How an attacker would use it

An attacker sees that test.c4lab.in uses DreamHost Mail for email and clones that provider's login page for a targeted credential-phishing campaign against your staff.

Why informational

Informational: no misconfiguration. Exposure is inherent to how these records work.

How to fix it

  1. Remove verification TXT records and SPF includes for services you no longer use. In your DNS hosting provider: Open the control panel of the provider that hosts the domain's DNS (the nameservers listed in this report) and add or edit the record there.
  2. Enforce multi-factor authentication on every listed service, especially the email provider (DreamHost Mail) and the DNS host (your DNS hosting provider), whose accounts control the domain.
  3. Brief staff that phishing will imitate these specific providers.

Rollback

Not applicable.

How to verify the fix

Run
dig test.c4lab.in TXT +short
Expect
Only records for services in active use.

Glossary

Terms used in this report

Attack surface
Everything about a domain that is reachable or visible from the internet: hostnames, IP addresses, open ports, services, software banners and third-party providers.
A / AAAA
DNS records mapping a name to an IPv4 (A) or IPv6 (AAAA) address.
CNAME
An alias from one name to another; the apex of a domain cannot normally be a CNAME.
MX
Mail exchanger records naming the servers that receive mail for the domain.
NS
Nameserver records naming the authoritative DNS servers for the domain.
SOA
Start of Authority: the primary nameserver, the responsible mailbox and the zone's timing values.
TXT
Free-form text records used for SPF, domain verification tokens and other policies.
CAA
Records naming the certificate authorities allowed to issue certificates for the domain.
HSTS
HTTP Strict Transport Security: a response header telling browsers to use only HTTPS for the site for a set period.
Banner
Software name or version disclosed in a response header, such as Server: Apache/2.4.58.
